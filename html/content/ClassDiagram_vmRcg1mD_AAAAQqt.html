Returning ref_cursors, part 1

One more benefit to point out, is the way in which ref_cursors are handled.

A primary use-cases for database packages, is to encapsulate query logic, allowing other systems to fetch data-sets without having to expose the SQL underlying them. This is most commonly done by returning a ref-cursor from which the consuming system can select.

Consider the model below. The xxschema.xxpub2.fn4 function is modeled to return a specifically structured set of data, whilst xxschema.xxpub2.fn5 returns a separate data structure.

The resulting generated code provides several options with which one can return the above data-set. The syntax and use-case for each of the ways is included in the generated database package specification.
